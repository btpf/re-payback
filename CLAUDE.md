# Payback reimplementation

Reverse engineering and Bevy reimplementation of Payback (Apex Designs, Amiga, 2001).

## Layout

- `crates/payback-formats/` — engine-agnostic parsers for the game's data files.
- `crates/payback/` — the Bevy 0.19 game. `crates/payback-mpeg/` — the Mac intro film (vendored `pl_mpeg`).
- `docs/` — reverse-engineering notes and project docs; `docs/README.md` is the index, `docs/CONVENTIONS.md` the rules (CONFIRMED with the original function, or INFERRED; citation format; quoting limits). Subsystem notes in `docs/re/*.md`, Mac reviews in `docs/re/mac/`, dated reviews in `docs/re/reviews/`, working notes in `docs/re/notes/`, the Mac↔OS4↔68k symbol table in `docs/xref/symbols.tsv`. Status and roadmap: `docs/status.md`.
- `tools/` (index: `tools/README.md`) — `extract/` (`extract.py` for the Amiga CD and updates, `extract_mac.py` for the Mac release, `hunk.py`), `ghidra/` (`decompile_all.sh` regenerates every export in `analysis/`; Ghidra scripts), `re/` (`fn.py` function lookup and `--sym` cross-build translation, 68k/OS4 disassembly helpers, decoders, the symbol matcher), `checks/` (`replay_check.py` determinism suite, `autoplay_all.sh`, `perf_check.sh`, `usermaps_smoke.sh`, `web_smoke.mjs`, `doc_links.py`), `reports/` (`coverage.py`, `mac_differences.py`), `web/` (`build_web.sh`, `pack_web_data.py`), `dist/stage_data.py`, `dev/buildgate.sh`.
- Game data at run time: the build stages the files listed in `crates/payback/data_files.txt` (one list, also used by the web pack) into `target/<profile>/data/amiga` and `data/mac` (`build.rs`; generated, ignored with `target/`), so the exe runs from any working directory. Search order and overrides (`PAYBACK_DATA`, `--data`, `payback-data.cfg`, `extracted/` above the exe or working dir, folder picker; `PAYBACK_NO_DIALOG=1`, `PAYBACK_STAGE_DATA=0`): `crates/payback/src/locate.rs`.
- `web/` — the WebAssembly loader (`index.html`); `web/dist/` is the git-ignored build output with the packed game data (`docs/web.md`).
- Mac release (`PaybackMac.toast`): treated as the more definitive copy; see `docs/re/mac_version.md`. Decompiles are in `analysis/ghidra_macx` (OS X build; functions keep their original C++ names), `analysis/ghidra_mac9` and `analysis/ghidra_mapedx`, next to the Amiga ones (`analysis/ghidra_68k`, `analysis/ghidra_os4`, `analysis/ghidra_scriptNN`).
- Git-ignored, each with one lifetime:
  - `Payback Game + Updates/` (the source data), `extracted/` (`tools/extract/`), `Saves/`, and `[A] PAYBACK 2025.7z` (ignore it entirely).
  - `analysis/` — Ghidra exports **only**, regenerated by `tools/ghidra/decompile_all.sh` (`docs/decompiling.md`). Never put hand-made files there.
  - `out/` — generated renders and check output. `scratch/` — throwaway work, safe to delete.
  - `target/`, `web/dist/`; the local report pages `progress.html`, `remaining_gaps.html`, `coverage.html` (`tools/reports/coverage.py`), `mac_differences.html` (`tools/reports/mac_differences.py`), `docs/required_files.html` (which original files are needed to compile, run and decompile).
- Never commit original game data, decompiled code (beyond a few quoted lines) or renders of the game's art.

## Working conventions

- Keep the original's behaviour; cite decompiled functions in doc comments (Mac name @ address, or `FUN_xxxxxxxx`, OS4 or 68k; `docs/CONVENTIONS.md`).
- Promote before you cite: committed code and docs must not point at `scratch/`, `out/` or anything ignored except `extracted/` and `analysis/ghidra_*`. A script you run twice goes into `tools/<area>/` with paths derived from the repository root (no `D:/...`) and a line in `tools/README.md`; one-off scripts go into `scratch/<date>-<topic>/`.
- Text files use LF line endings (`.gitattributes`).
- Builds: limit parallel cargo builds with `tools/dev/buildgate.sh`, e.g. `CARGO_TARGET_DIR=target/lead tools/dev/buildgate.sh cargo build -p payback -j 8`. Use `target/` (debug/release) or one named dir per agent, and delete per-agent target dirs when done.
- Verify visual changes with `./target/debug/payback.exe [--map N --level L] --screenshot <png>` and look at the image.
- Test runs must open in a normal window, never borderless or exclusive fullscreen (the user works on the same screen): point `PAYBACK_SAVES` at a scratch folder whose `Payback.cfg` has `window_mode = windowed` (or use a `--windowed` override if present). Never edit the user's real settings or saves.
- Use common sense when launching tests: run only the checks that can reveal a problem with the change. The replay suite and `PAYBACK_DET_CHECK` only for changes that can affect the simulation, replays or entity components (sim/, mission/, input, replay format, anything touching `Obj`); autoplay only for gameplay changes; screenshots for visual changes; nothing heavy for render-only, shader, HUD, menu, docs or tooling changes. The user shares the machine, so keep test runs few and short.
- Keep `cargo test -p payback -p payback-formats` passing. Keep replay determinism intact: `python tools/checks/replay_check.py --suite` (story, story2, rampage, multiplayer, cheats; `--exe` picks the build) or `tools/checks/replay_check.sh <name> <ticks> --map 0 --seed 1234` must report MATCH; `cargo test -p payback --test replay_determinism -- --ignored` runs the same suite. It compares the port with itself, never with the original. `tools/checks/autoplay_all.sh [exe]` plays the six story levels with the bot.
- Determinism rules (`docs/port_engineering.md`): render systems must not add/remove components on `Obj` entities; sim loops that draw rng, spawn, despawn or pick first-come iterate by object-table slot (`sim::table_order`), never by query order or `Entity`; sim state changes only in the fixed tick. `PAYBACK_DET_CHECK=1` reports violations of the first rule.

## Progress page

`progress.html` in the repository root is a self-contained page (no external assets) that shows the project's progress and what's left to do. It is git-ignored (local only). **Keep it up to date:** whenever a feature lands, a gap is found or fixed, or priorities change, update its `DATA` object.
