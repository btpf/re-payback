## Findings (differences)

### 1. Level 11 M1, event 0x6a (bomb explodes in range): the explosion RNG values go to the wrong axes

- **Mac**: `ProcessTrigger_11`, case 10137f88 (slot 1), `param_1 == 0x6a`, l.112456-112463.
  For each cell x 78..82 by y 110..113:
  ```
  if (random(2) == 0) {
    z = random(0x5dc); dy = random(0x800); dx = random(0x800);
    Explosion(x*0x800 + dx, y*0x800 + dy, z + 17000, 0, 3000);
  }
  AdjustCube(x, y, 1, 0x200, 0x200, 0,0,0);
  ```
- **68k**: the same order, z then y then x (ghidra_68k l.104077-104094, return addresses
  0xc4d9c, 0xc4dac and 0xc4dc4). **OS4** evaluates the arguments left to right: x, y, z
  (ghidra_os4 l.118843-118850).
- **Port** (`level_11.rs:367-371`): `ex = x*0x800 + random(0x800)`, then `ey`, then
  `ez = 17000 + random(1500)`. This follows the OS4 order. The port draws the same number of
  values, so the RNG stream stays in step, but each value lands on a different axis. With the
  same seed, the explosions go to different positions and heights than on the Mac or 68k.
- Classification: **port bug**. The Mac and the 68k agree, and the OS4 order is a compiler
  artefact.
- Recommendation: draw z, then dy, then dx, as `level_00.rs:756-758` already does for the
  matching level-00 M5 grid. Add the order to the `docs/re/missions_11.md` pseudocode (l.257),
  as `missions_00.md:397` already does. Replays that reach level 11 M1 will change. The map-0
  determinism check doesn't run this code.
- **CONFIRMED**.

### 2. Level 21 M7, event 740 (bomb truck explodes at the garage): the same explosion RNG order bug

- **Mac**: `ProcessTrigger_21`, case 1013d194 (slot 7), `param_1 == 0x2e4`, l.114413-114421.
  For x 124..127 by y 64..68: `if (random(1) == 0) { z = random(0x5dc); dy = random(0x800);
  dx = random(0x800); Explosion(x*0x800+dx, y*0x800+dy, z+17000, 0, 3000); }`.
- **68k**: z, y, x (ghidra_68k l.107658-107674, 0xc98e6, 0xc98f6 and 0xc990e). **OS4**: x, y, z
  (ghidra_os4 l.111252-111256).
- **Port** (`level_21.rs:768-772`): x, y, z, which is the OS4 order.
- Classification: **port bug**, the same as finding 1.
- Recommendation: `ez = 0x4268 + random(1500)` first, then `ey`, then `ex`. Fix the pseudocode
  in `missions_21.md:571`.
- **CONFIRMED**.

### 3. Level 21 M8, event 830 (phone self-destructs): the two random offsets are swapped

- **Mac**: case 1013d750 (slot 8), `param_1 == 0x33e`, l.114473-114475:
  `a = random(100); b = random(100); Explosion(b + 0x253ce, a + 0x3d3ce, 20000, 0, 1500)`.
  The first value is the **y** offset.
- **68k**: the same. The first `FUN_0003fc8c` result goes to `+0x3d3ce` (y) and the second to
  `+0x253ce` (x) (ghidra_68k l.107814-107819). **OS4**: the first goes to x (ghidra_os4
  l.111348-111350).
- **Port** (`level_21.rs:938-940`): `x = 0x253ce + random(100)` is drawn first. This is the
  OS4 order.
- Classification: **port bug**. The effect is cosmetic (a 100-unit jitter on a decorative
  explosion), but it is visible in replays.
- Recommendation: draw y first. Fix the pseudocode in `missions_21.md:604`.
- **CONFIRMED**.

### 4. Level 21 init: the car-50 destroyed trigger (known, missions.md §2.1)

Mac `InitScript_21` arms `AddTrigger(0x32, 9, 0x32)` (l.107347). The default branch of
`ProcessTrigger_21` (l.114554-114563) handles event 0x32 like this: Release(50), curSlot = 1,
StopStoredTriggers, Say(2, 5), Announce(2028), FinishMission. The 68k doesn't have this, so it
is a **Mac change**. **The port already has it**: `level_21.rs:127-130` (the trigger) and
`level_21.rs:215-222` (the handler, in the same call order as the Mac). CONFIRMED.

### 5. Level 20, event 200000 (escaped the prison): release order (no effect)

The Mac (l.113558-113572) releases the guards in this order: 300000-300003, then for i in 0..2
the triple 300100+i, 300300+i, 300500+i, then 300200, 300400, 300600, 300700, 300800. The port
(`level_20.rs:588-590`) releases them in `GUARDS` table order. The set of guards is the same,
and each `Actor_Release` is independent. Classification: no-op. Recommendation: none, or
match the order for fidelity. INFERRED: we assume the release order has no side effects.
