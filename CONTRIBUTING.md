# Contributing

## Workflow

- Work on `main` and keep history linear: rebase, don't merge. One commit per
  coherent change (a feature, a fix, a doc pass); the message says what changed
  and, for behaviour, which original function it follows.
- Before committing: `cargo test -p payback -p payback-formats` passes and
  `python tools/checks/replay_check.py --suite` reports MATCH for every case. For
  visual changes, run `cargo run -p payback -- [--map N --level L] --screenshot
  out/shot.png` and look at the image.
- When several builds run in parallel (agents), wrap cargo in
  `tools/dev/buildgate.sh` and use your own `CARGO_TARGET_DIR` under `target/`;
  delete it when done.

## Legal checklist

Nothing from `extracted/`, `analysis/`, `out/`, `scratch/` or `web/dist/` is ever
committed. No original files, no renders or screenshots of the game's art, no
decompiled function bodies (a few quoted lines are fine), no long game texts.
`git status` before every commit; `.gitignore` covers the usual places.

## Code

- Keep the original's behaviour. Cite the function you followed in the doc comment
  (Mac name @ address, OS4 or 68k `FUN_…`, see `docs/CONVENTIONS.md`) and the note
  that explains it (`docs/re/vehicles.md §2`).
- Deliberate departures (port additions, bug fixes, Mac vs Amiga choices) say so
  in the comment.
- Determinism (`docs/port_engineering.md`):
  - render systems never add or remove components on `Obj` entities
    (`PAYBACK_DET_CHECK=1` reports it);
  - simulation loops that draw random numbers, spawn, despawn or pick first-come
    iterate in object-table order (`sim::table_order`), never in query order or
    by `Entity`;
  - simulation state changes only in the fixed tick; nothing in it reads frame time.
- Text files use LF line endings.

## Findings

See [`docs/CONVENTIONS.md`](docs/CONVENTIONS.md). In short: find the note in
[`docs/README.md`](docs/README.md), tag the fact CONFIRMED (with the function) or
INFERRED (with the reasoning), cite Mac name @ address and/or OS4 / 68k `FUN_`
addresses, update [`docs/re/open_questions.md`](docs/re/open_questions.md), and add
new function names to the symbol cross-reference
([`docs/xref/symbols.tsv`](docs/xref/symbols.tsv), regenerated by `tools/re/symbols/`).

## Decompiles

`analysis/` holds only Ghidra exports. Regenerate them with
`tools/ghidra/decompile_all.sh` (Docker image from the `Dockerfile`;
[`docs/decompiling.md`](docs/decompiling.md)). Never put hand-made files there.
`tools/re/fn.py` prints functions from them.

## Tools and scratch work

- A script you will run twice belongs in `tools/<area>/`: paths derived from the
  repository root (no absolute `D:/...` paths), a usage line, an entry in
  [`tools/README.md`](tools/README.md). Write generated files to `out/`.
- One-off scripts, logs and dumps go into `scratch/<date>-<topic>/` (git-ignored,
  safe to delete). Committed code and docs never cite `scratch/`: promote the file
  first.
- The progress pages (`progress.html`, `remaining_gaps.html`) are local; keep
  `progress.html`'s `DATA` object current when something lands.
